6. EXTERNAL ATTENDEES – VIP MATCHING

When external attendees are entered, extract candidate names and compare with vips.json.
Example: "Nguyễn Văn Đức; Lê Văn Danh,\nThái Minh Giao"

Preprocess Unicode NFC, trim, collapse spaces, case normalization and punctuation. Split on semicolons, commas, newlines, bullets. Handle periods carefully because titles/abbreviations may contain periods. Preserve original input and do not assume all segments are person names. Extract title context, e.g. "Nguyễn Văn Đức (Chairman)" -> name "Nguyễn Văn Đức", title "Chairman".

Match in this order:
1. Exact normalized name
2. Accent-insensitive name
3. Fuzzy similarity (Levenshtein/Jaro-Winkler or equivalent)
4. Organization/title context to resolve ambiguity

No external paid AI API is required. Suggested configurable thresholds: >=0.95 high confidence; 0.80–0.95 needs review; <0.80 unmatched. These are starting thresholds, not identity proof. Auto-confirm only unambiguous strict matches. Require manual confirmation for similarly named VIPs.

UI shows extracted name, suggested VIP, department, title, score, status. Allow confirm/reject/search/replace. Never silently correct an uncertain name. Persist only confirmed IDs, using the actual VIP ID format from vips.json:
{"vip_ids":["VIP-202608-00001","VIP-202608-00003"]}
The IDs above are illustrative, not a mandated format.

8. MEETING FREQUENCY AND KPI LOGIC

VIPs have Meeting Frequency and Meeting Period:
- QUARTER: 4 periods/year
- HALF_YEAR: 2 periods/year
- YEAR: 1 period/year

Annual target = Frequency × Periods per Year.
Examples: 1/QUARTER => 4/year; 2/HALF_YEAR => 4/year; 1/YEAR => 1/year.

Each required meeting is a KPI slot. Assign eligible completed meetings to the period containing their meeting date. Count each meeting at most once per VIP. Cap counted meetings at that period's target; excess meetings must not transfer to another period.

Example: H1 target=2, actual H1 meetings=3 => completed H1 KPI slots=2; the third meeting does not count for H2.

Slot colors:
- Green: completed
- Red: overdue
- Gray: not yet due
- Yellow: in progress where aggregate UI supports it

Compute status from period deadlines and the selected as-of date; do not mark future slots overdue.
Annual KPI % = completed required slots / annual required slots × 100, capped at 100%.
YTD KPI % uses required slots with deadlines elapsed as of the selected date, including early completed slots. Distinguish Annual, YTD, Overdue and Not Yet Due.

On meeting edit, date change, delete or restore, recalculate affected periods.

KPI by PIC aggregates by responsible PIC from vips.json: PIC, VIP Count, Total KPI Slots, Completed, Overdue, Not Yet Due, Annual KPI Achievement. Derive from actual records; no hardcoded dashboard metrics.
