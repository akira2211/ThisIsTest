TASK: Update VIP Engagement KPI — Effective Date Exclusion Rules

1. Objective

Update the existing VIP Engagement KPI calculation to support effective-date-based KPI slot exclusion.

Currently, the system generates a fixed number of KPI circles for the entire year based on "meeting_frequency" and "meeting_period".

New requirement: KPI circles must be generated only for eligible periods, considering each VIP's "active_date".

Excluded KPI circles must be completely removed from the UI and all KPI calculations.

Do not redesign the existing UI or rewrite unrelated functionality.

The project uses:

- JSON-based storage
- "data/vips.json"
- "data/government_meetings.json"

Before implementation, inspect the existing source code, JSON schemas, KPI calculation functions, and frontend components.

Reuse the current architecture and existing functions wherever possible.

5. Effective Date Exclusion Rules

Use "active_date" to determine when the VIP becomes eligible for KPI calculation.

Evaluate the selected KPI year independently.

MONTH

- VIP active for the entire month: generate all configured slots.
- VIP active for only part of the month: generate 0 slots.
- VIP not yet active: generate 0 slots.

QUARTER

- VIP active for the entire quarter: generate all configured slots.
- VIP active for only part of the quarter: generate 0 slots.
- VIP not yet active: generate 0 slots.

HALF_YEAR

- VIP active for the entire half-year: generate all configured slots.
- VIP active for part of the half-year:
  - If active days / total period days > 60%, generate at most 1 slot.
  - Otherwise, generate 0 slots.
- VIP not yet active: generate 0 slots.

YEAR

- VIP active for the entire year: generate all configured slots.
- VIP active for part of the year:
  - If active days / total year days > 60%, generate at most 1 slot.
  - Otherwise, generate 0 slots.
- VIP not yet active: generate 0 slots.

Important:

- The threshold is strictly greater than 60%, not greater than or equal to 60%.
- Count calendar days inclusively.
- Correctly handle leap years.
- Compare dates using calendar dates, not local-time timestamps that could cause timezone errors.
- Respect any existing eligibility exclusions and historical activation/deactivation rules.
- Do not use "created_at" as the effective date when a valid "active_date" is available.

6. KPI Circle Generation

Previously:

"TotalSlots = MeetingFrequency × PeriodsPerYear"

New logic:

"TotalSlots = Sum(EligibleSlotsForEachPeriod)"

Example:

KPI Year: 2026
Meeting Frequency: 2
Meeting Period: QUARTER
Active Date: 2026-05-15

Q1: 0 slots (excluded)
Q2: 0 slots (excluded)
Q3: 2 slots
Q4: 2 slots

Total Valid Slots: 4

Only render the four valid circles.

Do not render excluded circles as gray, disabled, transparent, or placeholders.

The number of visible circles must exactly equal the number of valid KPI slots.

KPI Circle Status

Maintain existing color behavior:

- Green: completed slot.
- Red: incomplete slot in a closed period.
- Gray: incomplete slot in an open or future period.

If the existing UI supports an in-progress yellow state, preserve it without changing the eligibility rules.

7. Meeting Allocation

Allocate completed meetings to the period containing their meeting date.

Rules:

1. Count only valid completed meetings according to existing meeting-status logic.
2. Match meetings to the correct VIP using existing meeting associations.
3. A meeting must belong to the selected KPI year and an eligible period.
4. Completed meetings cannot exceed the number of valid slots in that period.
5. Extra meetings in one period must not complete slots in another period.
6. Prevent duplicate meeting records from being counted twice.
7. Do not count draft, canceled, deleted, or otherwise ineligible meetings.

Example:

Frequency: 2
Period: HALF_YEAR

H1 eligible slots: 1
H1 completed meetings: 3

H1 completed KPI slots: 1

H2 eligible slots: 2
H2 completed meetings: 0

Total completed KPI slots: 1
Total valid KPI slots: 3
Annual KPI: 33.33%

8. Annual KPI Calculation

Use:

"Annual KPI % = CompletedValidSlots / TotalValidAnnualSlots × 100"

Example:

Original annual slots: 8
Excluded slots: 4
Valid annual slots: 4
Completed valid slots: 3

Annual KPI = 75%

If total valid annual slots equals zero, return "N/A".

Do not return 0% when the denominator is zero.

9. YTD KPI Calculation

Use:

"YTD KPI % = CompletedSlotsInClosedPeriods / ValidSlotsInClosedPeriods × 100"

Important:

- Consider only eligible KPI slots belonging to closed periods.
- Do not include open or future periods in the YTD denominator.
- If no eligible period has closed, return "N/A".
- YTD = 100% does not necessarily mean annual KPI = 100%.

Example:

Frequency: 1
Period: HALF_YEAR

H1 completed: 1
H2 still open: 0

Annual KPI: 50%
YTD KPI: 100%

Use the selected reporting date or existing as-of date, not an unrelated server timestamp.

- Agency KPI → Agency Performance Overview

- Any existing KPI charts, counters, exports, or summary APIs

The following values must reflect the new logic:

- Total KPI Slots
- Completed
- Overdue
- Not Yet Due
- Annual KPI %
- YTD KPI %

For aggregate KPI percentages, use:

"Sum(CompletedValidSlots) / Sum(TotalValidSlots) × 100"

Do not calculate aggregate KPI by averaging individual VIP percentages.

For aggregate YTD, use the total completed closed-period slots divided by total eligible closed-period slots.

Avoid duplicating calculation logic in different pages.
