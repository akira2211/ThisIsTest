Task: Redesign VIP Engagement & Take-Care Reminder HTML Email

1. Objective

Redesign the existing VIP Engagement & Take-Care Reminder HTML email to closely match the visual design of the current SEHC Engagement KPI React dashboard.

The email must look like a modern enterprise dashboard rather than a plain HTML report.

Key architectural requirement:

The HTML structure and CSS must be implemented as a reusable, fixed template. KPI calculations, VIP classification, and report data preparation must remain separate from the presentation layer.

Do not generate a new HTML layout for every email execution. Only inject calculated data into the existing template.

2. Inspect Existing Implementation First

Before making changes, inspect:

- Existing React Engagement KPI dashboard components and their CSS/design tokens.
- Existing "vip_engagement_reminder" report definition and HTML renderer.
- Current report data preparation and VIP classification logic.
- Shared Email Engine template infrastructure.
- HTML preview and delivery execution paths.

Reuse the current architecture wherever possible.

Do not rewrite Email Engine, Scheduler, recipient groups, delivery history, or Agent Builder integration.

3. Visual Design Requirements

Create a professional dashboard-style email with:

- Maximum content width: 800px.
- White background with subtle light-gray sections.
- Samsung-inspired blue as the primary accent.
- Compact enterprise typography.
- Consistent table spacing and thin borders.
- Color-coded KPI cards and section headers.
- Grade badges (A/B/C) matching the React UI.
- Colored status badges for overdue, due soon, and on track.
- Clearly separated sections with comfortable spacing.

Use inline CSS and table-based layout for email compatibility.

Avoid dependencies on JavaScript, external stylesheets, CSS Grid, Flexbox, or unsupported browser-only features.

6. Fixed Template + Dynamic Data Architecture

Separate the implementation into three logical layers:

Layer 1 — Data Preparation

Reuse the existing report business logic to calculate KPI results and prepare a structured report model.

Example:

{
  "reportDate": "2026-10-18",
  "summary": {
    "totalVips": 23,
    "notYetMet": 12,
    "immediateAttention": 3,
    "dueSoon": 0,
    "onTrack": 8
  },
  "sections": {
    "notYetMet": [],
    "immediateAttention": [],
    "dueSoon": [],
    "onTrack": []
  }
}

The example values are illustrative only.

Layer 2 — HTML Template

Store the static email structure, CSS styling, section layouts, and placeholders in a dedicated template file.

Use the existing template system, or Handlebars if compatible with the current architecture.

Layer 3 — Renderer

Inject calculated report data into the fixed template.

The renderer should only format values, render rows, escape dynamic content, and apply visual styles.

It must not calculate business KPIs or independently classify VIPs.

Avoid large hardcoded HTML strings embedded directly in report calculation functions.

7. Email Compatibility

Optimize for Outlook and Knox Portal Mail.

Requirements:

- Inline CSS on all important visual elements.
- Table-based layout.
- No JavaScript.
- No external CSS.
- No dependency on CSS Grid or Flexbox.
- No externally hosted fonts.
- Readable fallback if rounded corners or shadows are unsupported.
- Proper UTF-8 encoding for Vietnamese names.
- Correct escaping of user-generated content.
- Appropriate column widths and text wrapping.
- No horizontal overflow at the intended 800px width where practical.

The final HTML must be delivered as HTML content, not escaped markup or plain text.

Do not redesign the React dashboard.

Do not change KPI business rules unless explicitly approved.

Do not introduce LLM-based HTML generation.

Do not hardcode sample KPI numbers in the production template.

Reuse existing components, styles, and utilities whenever possible.
